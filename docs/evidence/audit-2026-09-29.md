# Bug audit (2026-09-29)

Audit of the whole tree under `package/` and `tools/` after the cutover, done
against commit 8e39b57 (packages `mqtt-metrics` r5 and `luci-app-mqtt-metrics`
r5, as installed on both routers). The fixes are in `mqtt-metrics` r7 and
`luci-app-mqtt-metrics` r6.

## Method

- Read every source file with the hard invariants of `AGENTS.md` in mind
  (secrets, read-only, unavailable values, legacy defaults).
- For each suspected defect, write a test first. A test that fails on the old
  code is marked "reproduced" below; a defect found by reading only, where the
  fix added a new type, option or parameter that the old code cannot be tested
  against, is marked "reading".
- Compare the dry-run output (`mqtt-metricsd --dump`) of the fixed build with
  the installed r5 on both routers. This is read-only: it reads `ubus` and
  `/etc/config`, does not connect to the broker and does not touch the
  installed service. The fixed binary ran from `/tmp` and was removed
  afterwards.
- Run the LuCI views in headless Chromium against a stand-in for the LuCI
  runtime (`tools/luci-view-tests.browser.js`).
- An independent multi-angle code review of the same commit ran alongside;
  its result is recorded at the end of this file.

## Findings and fixes

### Wrong data in Home Assistant

| # | Defect | Evidence | Fix |
| --- | --- | --- | --- |
| 1 | A value that goes away kept its retained state. After a WAN went down, its address, gateway, device, latency and rates stayed on the broker and Home Assistant showed them as current while the router was online. The same held for a value missing at daemon restart and for an instance that disappeared (a WireGuard peer, a device). The legacy script cleared such values on its next run. | reproduced: `a_value_that_disappears_is_cleared_once_and_comes_back`, `restart_while_a_value_is_missing_clears_the_old_retained_state`, `a_vanished_instance_is_cleared_but_a_failed_group_is_not` | ADR-0006: an absent value is cleared once, a failed read (timeout, garbled answer) keeps the last value, an impossible entity is not announced. `a_failing_source_does_not_blank_published_values` covers the failed-read case. |
| 2 | Legacy adoption cleared the legacy topics while the crontab still scheduled `publish_metrics.sh`. The script published them again at the next run and the entities flapped. | reproduced: `legacy_adoption_waits_until_the_legacy_cron_line_is_gone` | The adoption waits until the cron line is gone (`legacy::cron_active`). |
| 3 | Protocol rules hid real data. DS-Lite, MAP and 464XLAT were treated as IPv6-only, so their IPv4 address was never announced. `ip6assign` did not count as IPv6 configuration. An address that existed was suppressed when the protocol list said it could not exist. | reproduced: `tunnels_that_carry_ipv4_are_not_ipv6_only`, `a_static_interface_with_a_delegated_prefix_can_have_ipv6`, `an_address_that_exists_is_never_hidden_by_the_protocol_rule` | The list is `dhcpv6`, `6in4`, `6to4`, `6rd`; an existing address is always published; the rule only decides whether a missing one is permanent. |
| 4 | Two instances with the same sanitized name (two WireGuard peers with the same description, `eth0.1` and `eth0_1`) got the same `unique_id` and topic and overwrote each other. | reproduced: `duplicate_names_get_distinct_entities` | Numeric suffixes `_2`, `_3`. |
| 5 | The link speed of an Ethernet port was "permanent" when the link was down, so the Home Assistant entity was removed and created again on each link flap. | reproduced: `a_missing_link_speed_is_permanent_only_for_devices_without_one` | Permanent only for devices without a `devtype` (PPP, tunnels). |
| 6 | Boot time, handshake age and HA sync age were computed from the wall clock before NTP had set it (a boot time near 1970 or a huge age). | reproduced: `nothing_is_derived_from_an_unset_clock` | Unavailable while the clock is before 2020-01-01. |
| 7 | Wildcard characters in an instance name (`+`, `#`, `/`) became part of a topic. | reading | `expand_topic` replaces them. |

### Daemon and MQTT

| # | Defect | Evidence | Fix |
| --- | --- | --- | --- |
| 8 | A broker that denies the birth subscription (ACL) answered SUBACK 0x80, which the client treated as a protocol error. The connection dropped and was rebuilt every few seconds, with a full pass each time. | reproduced: `a_denied_subscription_does_not_drop_the_connection` | The connection stays; one warning is logged; the Status page shows it. |
| 9 | The reconnect delay reset after every short connection, so a broker that accepted and then dropped the connection was retried every 5 s. After the broker settings were fixed in LuCI, a stale delay of up to 120 s was still waited out. | reading; `backoff_grows_and_resets_after_a_stable_session` | Delay 5 s doubling to 120 s; reset after a stable minute or a configuration change. |
| 10 | A second `mqtt-metricsd` could be started by hand and fought over the client id and the control socket. | reading; `a_second_instance_is_refused` | Lock file `/var/run/mqtt-metrics/daemon.lock`. |
| 11 | `mqtt-metricsd --purge` on a router with the service running cleared the topics, but the running service did not publish again. The entities stayed gone until the next restart. | reading | The CLI asks the running service through the control socket and falls back to a direct purge only when there is no service. |
| 12 | The connection test in LuCI sent the stored password to any host typed into the form, and ignored the TLS verify switch and the TLS switch. | reading; `the_stored_password_stays_with_its_broker` | The stored password is used only for the saved host and port, and never with a TLS downgrade. |
| 13 | Importing the broker settings from the legacy script stored an empty or wrong password when the line had a trailing comment, a shell escape or a variable expansion. | reproduced: `trailing_comments_and_shell_escapes_are_understood`, `concatenation_is_not_a_literal`, `a_password_line_that_cannot_be_read_is_an_error_not_an_empty_password` | Real parser; values only the shell can evaluate are refused with a reason. |
| 14 | The birth subscription could not be switched off in LuCI (LuCI cannot store an empty option). | reading; `the_birth_subscription_can_be_switched_off` | New option `identity.birth`. |

## Found and not fixed

| Item | Why it stays |
| --- | --- |
| A collection pass is sequential. `ubus` calls time out after 5 s (7 s with the kill) and other helpers after 20 s, so a wedged `ubusd` can hold a pass longer than the broker allows (1.5 times the keepalive) and the connection is dropped; a SIGTERM waits until the pass ends. | It takes 60-90 s of accumulated stalls with the default keepalive, which is a failure of the router itself. The soak saw no reconnect in 18.7 h. The service reconnects with backoff. |
| Each resolved broker address gets its own 5 s connect timeout, so a dual-stack broker that drops SYNs costs 10 s per attempt. Name resolution is bounded by the libc resolver (about 5 s with musl). | Bounded, and followed by the reconnect backoff. |
| `/etc/mqtt-metrics/secret` stays after uninstall. | Deliberate: a reinstall keeps the broker settings. Remove it by hand with the config. |
| A hostname change needs a restart of the service. | The node name is part of every topic. |
| The new broker password is stored and the service reloaded when Save is pressed, before Save & Apply commits the other broker settings, so the service can briefly try the old address with the new password. The password is not in UCI (ADR-0004) and cannot be staged. | Transient; the next reload connects with both new values. |
| The MQTT client tests are weak: removing the PINGRESP timeout or the QoS 1 acknowledgement handling from a scratch copy leaves them green. | Test quality, no defect in the client. To do. |
| The fixture sanitizer is a denylist. The WireGuard key pattern is fixed, but a field or address shape it does not know passes through. | Read the sanitized capture before committing it. |
| Duplicated helpers in the LuCI views and the collectors, the group list copied in three places, dead exports; the catalog call runs a full 20-process collection on each page load; the interface dump is cloned while parsed; the loop clones the configuration each second; `exec` polls every 10 ms. | Cleanup and efficiency findings of the review; nothing wrong is published. |
| `keepalive = 0` makes the client ping on every call. | Not reachable: the configuration accepts 5 to 3600. |
| The licence terms of the `ring` crate (used by rustls) were not re-checked in this audit. | ADR-0005 recorded the choice; check before a public release. |

## Live checks (read-only)

`mqtt-metricsd --dump` of the fixed build, run on each router against the
live `ubus` data, compared with the same dump from the installed r5:

| Router | Installed r5 | Fixed build | Difference |
| --- | --- | --- | --- |
| Primary 10.0.77.1 | 60 messages | 60 | none (uptime only) |
| Secondary 10.0.77.2 | 54 | 60 | 6 clears of state topics that r5 never clears: device, IPv4 address and IPv4 gateway of `wan`; device, IPv6 address and IPv6 gateway of `wan_6`. The secondary is the BACKUP node and its WAN is down |

The comparison was repeated at the end with the daemon extracted from the
packaged `mqtt-metrics-0.1.0-r7.apk` (SDK build, TLS enabled): the same
result on both routers, `--check-config` valid, the catalog call took about
0.57 s. The SDK build of both packages succeeds with the SDK's Rust 1.94.

Both routers stayed healthy during the audit: connected, RSS 2.5-2.7 MB, no
new warnings in `logread`, 57 and 50 `ubus` objects as before. Nothing was
installed, restarted or reconfigured; the temporary copies of the daemon in
`/tmp` were removed after each run.

8e39b57 and pass now.

runs the real daemon, built with its paths pointing into a scratch directory,
against fake `uci`/`ubus` commands and an in-process fake broker. It covers
the daemon loop, which the unit tests do not reach. All five scenarios pass:

## Independent review

A second review of the same commit (8e39b57) ran while the fixes were being
written: 17 finders, each reading the tree from one angle (line-by-line scans
of the MQTT stack, the daemon, config and rpcd, the collectors, LuCI and
packaging, and the tools; a removed-behaviour audit; Rust and JS/shell/Python
pitfall specialists; cross-module and cross-language tracers; wrappers and
proxies; conventions; reuse; simplification; efficiency; root cause). Their
claims were reproduced one by one by verifiers, which did not refute any of
the claims they checked.

It found again what the audit had found (stale retained values, the denied
subscription, the legacy import, the protocol rules, `test_connection`, the
Reset button, the birth topic, the link speed, the unset clock, the CPU
rows). It also found what the audit had missed, all fixed on this branch with
a test unless noted:

| Defect | Fix |
| --- | --- |
| A group that returned nothing once (netifd not ready at start, a failed `ubus` call, mwan3 started later) was dropped from the schedule until the next reconnect, and a full pass in that state cleared the group's retained topics. | The group is read again at its interval; a full pass keeps the entities of a group whose source failed. |
| A full pass that removed an absent entity's discovery config never announced it again when it returned (stale announce cache). | The entity loses its track; it is announced again. |
| The ledger of owned topics was shrunk and saved before the clears were delivered, so a connection lost in between orphaned the topics for good. | The ledger keeps them until the broker has acknowledged the batch. |
| A malformed TLS key file put the key into the error message (log, status file, LuCI). | Only the kind of failure is reported. |
| The Metrics page showed defaults while the configuration had an error, and the next Save deleted every override. The Broker and Metrics forms accepted port 0, a decimal keepalive and a name over 128 bytes, which the daemon refuses. | The catalog describes the settings that could be read; the validators match the daemon. |
| `set_password` without a password deleted the stored one; the legacy import deleted it when it could not read an `export` line. | Both are errors. |
| Every full pass ran every helper of every group, including `apk list --upgradable` and the `keepalived` dump, although the default install publishes from two groups. | A group is read only when a metric of it is switched on. |
| Every online message on the birth topic started a full pass; 5 messages per second cost a quarter of a core. | Passes caused by them are 30 s apart. |
| A metric with an interval longer than the shortest one in its group was published at a multiple of that interval. | Each metric has its own due time. |
| Disabling the service in LuCI stopped it and deleted its reload trigger, so enabling it again never started it. | The service is registered again after the stop. |
| An unreadable configuration (`uci` failed) left the service in `config_error` for good. | It is read again after 10 s, 20 s, up to 5 minutes. |
| mwan3 latency and loss were published as 0 when `check_quality` is off, and every number of an interface without state as 0; the package count was 0 without a cached index; a stopped service kept ON. | Unavailable, unavailable, OFF. |
| `Unknown Model`, `Unknown Platform` and `Unknown Version` were published when the file was missing (the legacy script did the same). | Unavailable; listed as a difference from the legacy script in TOPICS.md. |
| `status.json` was not refreshed while waiting to reconnect, and showed `connected` after the service was disabled. | Refreshed. |
| Diagnostics actions had no error path; the LuCI RPC declarations did not reject failed calls. | Failures are shown. |
| `check.sh` never built or tested the `tls` feature that the package ships. | Both feature sets run. |
| `exec` could panic when a thread could not start and could wait on a pipe held by a process the helper left behind. | An error, and a 2 s grace. |
| `--import-legacy` printed the broker host and user. | It prints whether a password was set. |
| Turning `broker.retain` off left every earlier retained state on the broker for new subscribers to read. | The retained copy is cleared once, then states go out without retain. |
| The availability topic was not among the owned topics, so a base topic or node changed while the service was stopped left the old one behind. | It is owned and cleared like the others. |
| A stray byte in the output of `uci show network` made the whole Interface and Traffic groups unreadable; output cut at the size limit was parsed as if complete. | Lenient decoding; cut output is an error. |
| The Topics page dropped its identity warning after the first Save and its warning text named the wrong fields; the Broker page showed a password and TLS state it did not know when the service did not answer; the browser could fill the router login into the broker fields; failed calls printed a stack. | Fixed and covered by `tools/luci-real.browser.js`. |
| Tools: `parity-check.py` accepted any missing address topic as a documented removal; `soak-report.py` ignored the time the daemon was down; the sanitizer missed WireGuard keys that start with `+` or `/`; `cutover.sh` waited 60 s for a process that was its own shell; the browser scripts printed the router password in a Playwright error; the round-trip script edits the configuration without asking. | Fixed. |

## Deployment (2026-09-30)

Confirmed by the owner in chat, secondary first. `tools/deploy.sh` installed
`mqtt-metrics-0.1.0-r7` and `luci-app-mqtt-metrics-0.1.0-r6` over r5 on both
routers; the r5 packages are kept outside the repository for a rollback.

| | Secondary 10.0.77.2 | Primary 10.0.77.1 |
| --- | --- | --- |
| `ubus` objects before / after | 50 / 50 | 57 / 57 |
| LuCI `/ubus`, rpcd object `mqtt-metrics` | ok, present | ok, present |
| Retained topics on the broker before / after | 17 states, 22 configs / the same | 23 states, 22 configs / the same |
| Changed by the upgrade | `system/uptime` only | `system/uptime` only; no discovery config changed |
| Availability | `online` | `online` |
| After the first ticks (300 s and 600 s / 300 s) | connected, 0 reconnects, 0 publish errors, no warning in the log | the same |
| Daemon | RSS 2.6 MB, 1 thread, 6 file descriptors | RSS 2.6 MB, 1 thread, 6 file descriptors |
| HA cluster | not touched | role MASTER, state HEALTHY before and after |

The 6 extra clears predicted for the secondary (see Live checks) found nothing
to remove on the broker: those topics were already gone.

The upgrade left `/etc/config/mqtt-metrics.apk-new` (the packaged default,
which gained a `birth` option) on both routers. The live configuration needs
none of it, and the sidecar was removed. `state.json` now lists the
availability topic (45 owned topics instead of 44).
